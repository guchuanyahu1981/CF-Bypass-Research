## 与 `docs/` 的分工

- `docs/` = **是什么**（架构、接口契约、研究结论、运维手册）
- `plans/` = **接下来做什么**（迭代计划、任务分解、验收标准、证据）

单一事实源是 `docs/项目规格.md`（见指南 §15）。任何"结论被推翻"必须改正文并留痕，不允许只在行内加注记。

## 新增一份计划的命名规则

`plans/<动作>-<对象>-v<起版本>→v<止版本>.md`，例如：
`plans/吞吐升级-v2.5→v3.0.md`。
