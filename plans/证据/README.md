# 证据落地目录

验收时把**实际运行的命令与原始输出**存到这里，文件名用 `T-<任务号>-<主题>-<YYYYMMDD>.txt`。

> **为什么是 `.txt` 而不是 `.log`**（T-69 起）：`*.log` 已被 `.gitignore` 判为**运行产物**
> （服务日志、soak 日志都是程序自动重写的）。证据是"命令输出的快照"，不会被程序改写，
> 因此用 `.txt` 与运行日志在扩展名上区分开 —— 否则规则会禁止自己要求的东西。


规则：

1. 只放**原始输出**，不放总结（总结写进指南或 `docs/项目规格.md`）。
2. 不粘贴任何凭证：`cf_clearance` 的值、token、cookie 内容必须替换成 `<redacted>` 或只留长度。
3. 每条证据文件首行注明：命令、机器、日期、基线 commit。
4. 没有对应证据文件的验收项，一律视为**未验收**。
5. **可进/不可进的三条硬规则**（v6.0 / T-69 起生效，`scripts/check_repo_hygiene.py` 强制）：
   - ✅ **不可再生**：命令输出、JSON/Markdown 报告、截图。❌ 可再生或被程序重写的（`*.sqlite3*`、`salt.bin`、`pid.txt`、`*.log`、`.env`）
   - ✅ **无凭证**：入库前过 `python scripts/corpus.py redact --check`。❌ 任何 `cf_clearance` 值 / token / cookie 明文
   - ✅ **体积 < 200KB**：超了只放摘要 + 生成命令（原始数据留在本机 `corpus/` 或临时目录，并在文件首行写路径）

> **为什么加第 5 条**：2026-11-03 之前本目录跟踪过 7 个运行产物（缓存库 + salt + pid + 两份日志），
> 它们既可再生、又让"证据"与"运行态"混在一起，还让一次 `git add -A` 有带走 `.env` 的风险。
> 细节见 `scripts/check_repo_hygiene.py`（v6.0 T-69）。
