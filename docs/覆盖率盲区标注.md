# 覆盖率盲区标注

> 数据源：`coverage.json`（2026-11-12 全量测试，1155 passed / 8 skipped；`--cov=solver --cov=captchas/`）。
> 本文回答的是「**这些行为什么没覆盖、要不要补**」，不是重复一个总覆盖率数字。

口径：

- **不可达**：在当前进程/入口下没有执行路径，或只在退出/脚本入口发生。
- **需真机**：需要真实浏览器、真实挑战页、真实目标站；离线替身无法稳定复现。
- **故障注入**：正常路径已覆盖，剩下的是「库/文件/网络故意损坏」的分支；只有注入异常才走得到。
- **值得补（已补）**：本轮新增用例覆盖。
- **值得补（未补）**：纯逻辑，可以用替身稳定覆盖，但本轮没做（按价值排序保留）。
- **平台分支**：只在特定 OS/文件系统/库版本下出现。

## 4. 结论

- `solver/` 的缺口集中在**进程/真机/故障注入**三类；纯逻辑里仍有「值得补（未补）」的少量入口（HTTP 集成、research 坏文件、`_probe_for_route`、兼容层错误映射），按价值排序保留，不影响主链路。
- `captchas/` 的低覆盖是**能力边界**：11 个厂商主体必须在真实挑战页上执行；本轮把四个可离线验证的坐标/加密/预处理/选择器模块抬到了 35–71%。
- 新增用例没有为覆盖率写空断言：每条都对应一个会算错坐标、解不开密文、贴错 tile 或选错下拉项的真实失败模式。
