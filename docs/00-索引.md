## 七、依赖决策记录（T-81「只引一个」纪律）

> 原则：**每个新依赖必须先写进决策表再进锁文件**；运行期依赖默认 0 增长，
> dev 依赖按"补真实缺口"批准。本节与 `requirements-dev.txt` 头部注释块互为镜像。

| 候选 | 替换掉什么 | 收益 | 代价 | 结论（v5.0.4） |
|---|---|---|---|---|
| `prometheus_client` | `solver/metrics.py` 手写渲染（37 行，95% 覆盖） | 标准化 HELP/TYPE、histogram 分位数现成 | 引入持续维护的运行期依赖；现有手写已 95% 覆盖且 0 缺陷 | **不引**（收益不足；若将来要 histogram 分位数，先手写 20 行再看） |
| `hypothesis`（dev） | 手写边界用例 | 性质测试自动打 HTTP 参数面（超长 URL / 畸形 JSON / 极端 header） | CI 时间 +30s，需写策略 | **引（dev）**：补 §1.4 健壮性测试缺口；落点 `tests/test_properties.py`（`--hypothesis-profile=ci` 可加压到 200 examples） |
| `ruff`（dev） | 无（此前零 lint） | 静态检查（pycodestyle errors + pyflakes），CI 30 秒 | 需修历史告警 | **引（dev），只开 E/F 规则集**（`ruff.toml`：select=["E","F"], line-length=120），且只检查改动文件，不全仓强推 |
| `mypy`（dev） | 无 | 类型检查 | 现有代码无注解，全量跑必红 | **不引**（改造成本 >> 收益）；若将来做，先给 3 个核心模块加注解 |

锁版本：`hypothesis==6.170.14`、`ruff==0.14.9`（`pip freeze` 实取）。
