# 运维：压测与自检

> 三个工具解决三类问题：**环境对不对**（doctor）、**快不快/稳不稳**（loadtest）、
> **提交敢不敢合**（run.ps1 verify）。

---

## 1. `scripts/doctor.py` —— 环境自检

```bash
python scripts/doctor.py                 # 全量（会真起一次服务打 /health，约 20-30s）
python scripts/doctor.py --offline       # 只查环境，不启服务
python scripts/doctor.py --json          # 机器可读（给部署脚本用）
```

**退出码**：`0`=全绿 / `1`=有可降级项（能用但非最优）/ `2`=阻断项（起不来）。

它检查的东西（每一条都对应一个"曾经排查 40 分钟"的坑）：

| 检查 | 为什么 |
|---|---|
| Python ≥3.10 | 代码用了 `X \| Y` 类型语法 |
| camoufox / playwright / cryptography | 缺 camoufox 起不来；缺 cryptography 会静默降级成内存缓存 |
| **camoufox 二进制**（单独 fetch） | 缺它的表现是"服务 ready 但一求就挂" |
| 落盘缓存写读往返（SQLite/WAL） | 目录不可写 → 降级；这里提前暴露 |
| token 文件 | 没有会首启生成；但多 worker 必须**同一个** |
| 可选后端（cfsolve / Chrome） | 缺了不阻断，但你会一直在跑 16-20s 的浏览器路线 |
| 端口可用 | Windows 上端口冲突的表现是"服务起来了但响应是别人的" |
| **真起一次服务并等 ready** | 唯一可信的端到端答案 |

## 2. `scripts/loadtest.py` —— 离线压测

**默认全部离线**：本地假服务，不打真实站点、不烧出口 IP。

```bash
python scripts/loadtest.py --mode hot   --workers 8 --duration 5    # 回放吞吐（E2/A2）
python scripts/loadtest.py --mode cold  --workers 16                # 准入与去重（E1/F2）
python scripts/loadtest.py --mode share --processes 4 --iterations 3 # 多进程缓存（G2/A3）
python scripts/loadtest.py --mode hot --dry-run                      # 只看计划
python scripts/loadtest.py --mode hot --json                         # 给 evidence/ 用
```

本机实测（v4.0/v4.1，开发机）：

| 模式 | 结果 | 验收线 |
|---|---|---|
| hot（8 线程 × 5s） | **2874.9 QPS**，p50 2.64ms / p99 5.91ms，0 错 | ≥50 QPS ✅ |
| cold（16 并发） | 16/16 accepted，`solves_per_request=1.0` | 不被拒、每请求 1 次求解 ✅ |
| share（4 进程 × 3 轮） | sequential 每轮只解 1 次（3 次/3 轮） | 先后到达只解一次 ✅ |
| share burst（同时起） | **3 轮 3 次**（1 次/轮，0 浪费） | ✅ v4.4 加了 `claims` 抢占后同时也只解一次 |

> `share` 模式刻意分 sequential 与 burst 两阶段：前者是文档承诺（验收看它），
> 后者把"已知限制"量化出来，避免有人以为多进程能防住同时撞车。

## 2.5 `scripts/soak.py` —— 长跑稳定性

```bash
python scripts/soak.py --solver http://127.0.0.1:8971 --pid <服务PID> \
    --duration 3600 --interval 10 --probe-every 60 --auto-every 120 \
    --out plans/证据/soak.jsonl
```

按间隔采样 RSS / 句柄数 / `state` / 探测耗时，并施加**轻量真实负载**
（`/detect` 交替覆盖缓存命中与穿透、`route=auto` 打无盾站走 skip 分支 —— 都不消耗过盾预算）。

判定（不达标非 0 退出）：轻量端点错误率 == 0、始终 ready、RSS 增长 ≤80MB、句柄增长 ≤50。
默认**不做真求解**（`--solve-every 0`），要烧预算必须显式给间隔。

## 2.6 池演练（E5：崩溃隔离）

```bash
# 4 个 worker（共用 cache-dir）先起来，然后：
cd gocfsolve && go run ./examples/pooldrill   -nodes http://127.0.0.1:8981,http://127.0.0.1:8982,http://127.0.0.1:8983,http://127.0.0.1:8984   -duration 65s -interval 1s -probe 2s
# 演练中在另一个终端 kill 一个 worker，再重启它，观察 healthy 变化的时刻
```

本机实测（v4.3）：**摘除 2s**（maxFailures=2 + 探活 2s）、**回归 28s**（受 30s `downDuration` 支配），
其余节点全程 `f=0`。`-final-get` 默认关闭：用无盾站去做 Get 会真的求解并超时，那是脚本设计问题。

## 3. `run.ps1` —— 统一入口

```powershell
.\run.ps1 doctor         # 环境自检
.\run.ps1 test           # Python 全量 + 覆盖率门槛 80%
.\run.ps1 quick          # 改一处代码时的定向快测
.\run.ps1 go             # go vet + go test -race
.\run.ps1 findings       # 结论库证据链校验（需 node）
.\run.ps1 smoke          # 起服务 → /health → /detect → SSRF 守卫
.\run.ps1 bench          # 三个压测模式
.\run.ps1 verify         # 提交前必跑：以上核心项全跑
.\run.ps1 start / stop   # 前台启动 / 按端口停进程
```

`run.bat` 是同一套子命令的 cmd 包装。

**四类验收**（`accept` 的组成，缺一项即不算完整）：

| 轨道 | 命令 | 证据 |
|---|---|---|
| UI 截图 | `run.ps1 ui` | `plans/证据/ui-*.png` + `evidence/ui-acceptance.json`（含 axe/每个按钮/键盘/深色/320px） |
| 真实调用 | `run.ps1 realcalls` | `evidence/realcalls.json`（46 项：端点/方法/keep-alive/chunked/审计） |
| 真实 E2E | `run.ps1 e2e` | `evidence/e2e-local.json`（真进程 + 真浏览器，40 项） |
| 代码复审 | `run.ps1 review` | `evidence/code-review*.md`（`claude -p` 独立进程，`VERDICT` 逐领域） |

汇总：`python scripts/acceptance_report.py` → `evidence/acceptance.json`；缺证据、axe 违规、
任一轨道失败、复审 FAIL，都会让 `accept` 退出码非 0。

**退出码约定**：任一子命令失败 → 非 0。脚本用 `$LASTEXITCODE` 判断原生命令
（PowerShell 5.1 下若用 `$?`，pytest 往 stderr 写 warning 会被误判为失败——这个坑已写在脚本注释里）。

## 4. 真机实验（要用预算，别乱跑）

```bash
# 同站双臂 persona A/B（每站都分别被两个臂打过，才是可归因的对照）
python scripts/ab_persona.py \
  --pinned http://127.0.0.1:8941 --random http://127.0.0.1:8942 \
  --sites steamdb.info,glassdoor.co.uk --repeats 3 --budget 36 --gap 30 \
  --out plans/证据/v41-persona-ab.json

# 老的多站复测（站点间对照，口径较弱，保留兼容）
python scripts/verify_real.py --budget 20 --gap 30
```

硬纪律（脚本已内置，别绕过）：

1. 只发 GET 首页；不登入、不提交；
2. 同站相邻尝试间隔 ≥30s；
3. **累计失败 ≥5 立即全停**，隔 24h 再评估，不许换 IP 立刻重试；
4. 凭证只记长度，不落明文；
5. 必须支持 `--dry-run`。

> 为什么 `--force`：不强制重新求解的话，第 2 次起会命中服务端缓存（实测 0.5s 返回），
> 测到的就是"缓存多快"而不是"persona 差异"——A/B 会直接失去归因力。
